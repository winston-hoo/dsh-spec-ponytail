fix(ruleset): never lazy about function-bearing optional params & irreversible writes

Hardening after a real incident where urge was built as "drop remark + call
the endpoint straight from a click" (optional fields and irreversible/external
write actions were traded away as laziness).

Embed two new guards in the resident ruleset (lib/ruleset.js) and the full
skill (skills/ponytail/SKILL.md), kept in sync:
  - Optional != droppable: an API field marked optional is still passed when
    this flow uses it (remark/reason), not deleted because the schema allows empty.
  - Irreversible or third-party writes (notify, void, reverse, reopen, money)
    go through a confirm dialog with a reason — never straight off a click.
    Test: "can I undo it? does it reach a third party?" yes to either => confirm.

and kept the Intensity table wording aligned with LEVEL_LINE.
